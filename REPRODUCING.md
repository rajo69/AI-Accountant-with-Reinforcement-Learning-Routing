# Working from a fresh clone

How to set the repository up in an empty folder, rerun the evaluation, try
changes, retrain and regenerate the data without breaking the committed
results. Everything below was run on 22 November 2026 in new, empty folders on
Windows 11 with Python 3.12.8 (and is run by CI on Ubuntu with Python 3.12).

## 1. Set up

Use Python 3.12, the version CI tests. On Windows, if `py -0` does not list
3.12, [uv](https://docs.astral.sh/uv/) can fetch it for the virtual
environment.

Windows (PowerShell):

```powershell
git clone https://github.com/rajo69/AI-Accountant-with-Reinforcement-Learning-Routing.git
cd AI-Accountant-with-Reinforcement-Learning-Routing
uv venv --python 3.12 .venv          # or: py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt   # with uv: uv pip install -r requirements.txt
```

Linux or macOS:

```bash
git clone https://github.com/rajo69/AI-Accountant-with-Reinforcement-Learning-Routing.git
cd AI-Accountant-with-Reinforcement-Learning-Routing
python3.12 -m venv .venv && source .venv/bin/activate
python -m pip install -r requirements.txt
```

If PowerShell refuses to run `Activate.ps1`, skip it and call
`.venv\Scripts\python.exe` in place of `python`. The install pulls in PyTorch
(through Stable Baselines3), so the first one is large. Run every command from the repository root with `python -m ...`; no
`PYTHONPATH` setting is needed. No API key and no `.env` file are needed for
anything except regenerating the dataset (section 6).

Versions in the tested environment: torch 2.15.0 (CPU), stable-baselines3
2.9.2, gymnasium 1.4.0, numpy 2.5.5. The committed models were trained with
stable-baselines3 2.7.1 and load and score identically under 2.9.2.

## 2. Check the install

```bash
python -m pytest
```

21 tests, about 15 seconds. They write only to temporary folders.

## 3. Rerun the evaluation

```bash
python -m experiments.reproduce --check
```

This re-evaluates the committed models on the committed held-out sets for all
four regimes (raw, calibrated, regime, regime_raw), regenerates the statistical
summaries and re-evaluates the 30 multi-seed models, in about 30 seconds on a
laptop CPU. `--check` then compares every file under `experiments/`, `models/`
and `data/` with the last commit and prints `CHECK PASSED` when nothing changed,
which means every committed number was reproduced. It needs a clean working tree
to start from. `make reproduce-fast` runs the same steps where GNU Make is
installed, and the Docker route in the README needs neither Python nor Make.

The scenario-level comparison table under Results in the README comes from a
separate re-analysis and is not regenerated by this command.

## 4. Try a change without touching the committed results

Every training and evaluation command takes `--suffix`, which writes new files
beside the committed ones instead of replacing them:

```bash
python -m agent.train --reward A --suffix _try1     # about 10 minutes each on a CPU
python -m agent.train --reward B --suffix _try1
python -m agent.train --reward C --suffix _try1
python -m agent.evaluate --suffix _try1
python -m experiments.statistical_analysis --suffix _try1
```

That creates `models/trained/ppo_variant_{A,B,C}_try1.zip`,
`experiments/results/training_meta_{A,B,C}_try1.json`,
`experiments/results/evaluation_results_try1.json` and
`experiments/results/statistical_summary_try1.{json,md}`, to compare with the
committed `evaluation_results.json` and `statistical_summary.md`. For another
regime, pass the same `--dataset` (for example `--dataset regime`) to all five
commands. `agent.evaluate` stops without saving if any of the three models for
that dataset and suffix is missing, so a partial run never replaces a complete
results file. Delete or commit the suffixed files when you are done.

`--seed N` overrides the training seed in `agent/policy_config.yaml` (42).
Retraining with the same seed on another machine or library version is not
guaranteed to give a byte-identical model, so compare action totals and
metrics, not model files.

## 5. Which command replaces which file

| Command | Replaces (committed) | Also writes (git-ignored) |
|---|---|---|
| `agent.evaluate --dataset D` | `experiments/results/evaluation_results_D.json` | |
| `experiments.statistical_analysis --dataset D` | `experiments/results/statistical_summary_D.{json,md}` | |
| `experiments.multi_seed --eval-only` | `experiments/results/multi_seed_summary_*.{json,md}` | |
| `agent.train --reward V --dataset D` | `models/trained/ppo_variant_V_D.zip`, `experiments/results/training_meta_V_D.json` | `models/trained/best_ppo_variant_*`, `models/checkpoints/`, `experiments/tensorboard/`, `experiments/results/evaluations.npz` |
| `experiments.calibrate` | `data/generated/transactions_calibrated.jsonl`, `data/evaluation/held_out_set_calibrated.json`, `experiments/results/calibration_report.json` | |
| `experiments.regime_probe --source calibrated\|raw` | `data/generated/transactions_regime[_raw].jsonl`, `data/evaluation/held_out_set_regime[_raw].json`, `experiments/results/regime_probe[_raw]_report.json` | |
| `environment.transaction_simulator --overwrite` | `data/generated/transactions.jsonl`, `data/evaluation/held_out_set.json` | `data/generated/DATA_CARD_generated.md` |
| `environment.transaction_simulator --dry-run` | nothing | `data/dry_run/` |

For the raw regime the `_D` part is empty (`evaluation_results.json`,
`ppo_variant_A.zip`). With `--suffix S`, `S` is appended and nothing committed
is replaced. Training without a suffix replaces the models the README's numbers
come from, so do it on a git branch. Result files record repository-relative
paths, so a rerun in another folder does not change them.

## 6. Regenerate the dataset (calls the Anthropic API)

The committed models and results were all built from the committed dataset, so
regenerating it starts the whole pipeline again. Work on a git branch.

1. Set the key in the shell; the scripts do not read `.env`:
   `$env:ANTHROPIC_API_KEY = "..."` (PowerShell) or
   `export ANTHROPIC_API_KEY=...` (bash).
2. `python -m environment.transaction_simulator --overwrite --strict`.
   Without `--overwrite` it refuses to replace the committed files. Without
   `--strict` a failed API call falls back to template variants or a mock
   score and the run carries on, as happened for 16 seeds and 2 rows of the
   committed data (`data/generated/README.md`); the run now prints how many
   fallbacks it used. The default model is `claude-haiku-4-5-20251001`; pass
   `--model` if that one is retired.
3. `python -m experiments.calibrate`, then
   `python -m experiments.regime_probe --source calibrated` and
   `python -m experiments.regime_probe --source raw`.
4. Retrain every variant on every regime (`make reproduce-full`, or the
   `agent.train` loop it runs), then run section 3 without `--check`.
5. The simulator writes its statistics to `data/generated/DATA_CARD_generated.md`
   and never overwrites `data/generated/README.md`, the hand-corrected data card
   for the committed data. Update that card by hand for the new data.

`python -m environment.transaction_simulator --dry-run` tests the simulator
with mock data and no API calls. It writes only to `data/dry_run/`
(git-ignored) and gives the same mock data on every run. The other steps keep
reading the committed data, not `data/dry_run/`.

## 7. Known limits

- Some code comments and help texts still call the recalibration "Platt-scaled";
  the README's "logistic recalibration with tier and amount" is the accurate
  description.
- The routing API assumes `difficulty_tier` 1 when it is not sent (see
  Running the API in the README).
- An existing clone made before 19 November 2026 will hit a conflict on
  `.claude/settings.local.json` at the next `git pull`, because that file is
  now deleted upstream and git-ignored: copy the file somewhere, run
  `git checkout -- .claude/settings.local.json`, pull, then copy it back.
